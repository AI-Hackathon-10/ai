## 1. HTTP 엔드포인트 (`tests/test_main_identify.py`)

`TestClient`로 요청 파싱·응답 JSON만 본다. Vision/매칭은 monkeypatch.

| 대상 | 입력 | 기대 |
|------|------|------|
| `POST /identify` | `data:image/png;base64,...` | mime type이 `image/png`로 전달 |
| `POST /identify` | 순수 base64 + `front_mime_type` | 지정한 mime type 그대로 전달 |
| `POST /identify` | `front_image: ""` | **400** |
| `POST /identify` | 잘못된 base64 | **400**, detail에 `front_image` |
| `POST /identify` | vision 실패 mock | `vision_failed: true`, `match_result: null` |
| `POST /vision/extract` | PNG data URI | 매칭 없이 추출 결과만. `print_front=TYLENOL`, `print_back=500`, `color_class1=하양` |
| `POST /vision/extract` | 추출 실패 mock | `vision_failed: true`, `result: null` |
| `POST /vision/extract` | 빈 `front_image` | **400** |
| `POST /identify/db` | PNG data URI | `vision_result.print_front=YH`, `match_result.status=SINGLE_MATCH`, 후보 `item_seq=200808877` |
| `POST /identify/db` | 추출 실패 mock | `vision_failed: true`, `vision_result`/`match_result` 둘 다 null |
| `POST /identify/db` | 빈 `front_image` | **400** |

`/identify/db` 성공 케이스 응답 형태:

```json
{
  "vision_failed": false,
  "vision_result": { "print_front": "YH", "color_class1": "노랑", "drug_shape": "원형" },
  "match_result": {
    "status": "SINGLE_MATCH",
    "query_level_used": "STRICT_WITH_PRINT_FRONT_ONLY",
    "candidates": [
      {
        "item_seq": "200808877",
        "item_name": "페라트라정2.5밀리그램(레트로졸)",
        "print_front": "YH"
      }
    ]
  }
}
```

## 2. 파이프라인 (`tests/test_pipeline.py`)

| 시나리오 | 기대 |
|----------|------|

## 3. 매칭 레벨 (`tests/test_pill_matching_service.py`)

신뢰도 임계값 0.6, 후보 상한 10건. 구체적인 조건부터 완화한다.

| 시나리오 | 사용한 레벨 | 상태 |
|----------|-------------|------|
| 앞뒤 각인 신뢰도 높고 1건 | `STRICT_WITH_PRINT_BOTH` | `SINGLE_MATCH` |
| 앞면만 신뢰도 높음 | `STRICT_WITH_PRINT_FRONT_ONLY` | `SINGLE_MATCH` |
| 앞뒤 모두 높은데 BOTH가 0건 | `STRICT_WITH_PRINT_FRONT_ONLY`로 구제 | `SINGLE_MATCH` |
| 앞뒤 각인 신뢰도 낮음 | 각인 건너뛰고 `SHAPE_AND_COLOR` | `MULTIPLE_MATCHES` (2건) |
| 모든 레벨 0건 | `ALL_LEVELS_EXHAUSTED` | `NO_MATCH` |
| 마지막 `COLOR_ONLY`에서도 37건 | `COLOR_ONLY` | `TOO_MANY_CANDIDATES` |
| 클라이언트가 `find()`를 제공 | 전체 카탈로그 `get_catalog()`를 부르지 않고 필터 조회 | `SINGLE_MATCH` |

## 4. `pill_identification` SQL (`tests/test_pill_identification_repository.py`)

실제 MySQL 없이 SQL 문자열·매핑만 검증.

| 시나리오 | 기대 |
|----------|------|
| `PRINT_FRONT=TY 500`, 모양·색 포함 | 각인은 `REPLACE(LOWER(...))`, 공백 제거 후 `ty500`. 모양/색은 `TRIM`. `LIMIT 11` |
| 빈 필터 | SQL을 만들지 않음 (`None`) |
| DB row → 모델 | `item_seq=200808877`, `print_front=YH`, `drug_shape=원형`, `color_class1=노랑` |
| `find()` | cursor `execute` 1회, 매핑된 1건 반환, 연결 `close` |

## 9. Swagger `/vision/extract` 500 (2026-08-20)

재현: Swagger Try it out으로 실제 PNG data URI를 `POST /vision/extract`에 보냄.

원인:
1. `gemini-3.7-flash`가 `503 UNAVAILABLE` (high demand)을 반환
2. `GeminiVisionError`를 라우터가 잡지 못해 Starlette가 `500 Internal Server Error` (text/plain)로 응답

조치:
- Gemini 장애는 **503 JSON** `{"detail": "Gemini Vision 호출 실패: ..."}` 로 반환
- Swagger 기본값 `back_image`/`back_mime_type`의 `"string"`은 없는 값으로 무시

자동화: `test_vision_extract는_Gemini_장애시_500이_아니라_503_JSON을_반환한다`
